# Environmental storytelling — Pass 5

Pass 5 replaces overlapping generic tabletop clutter with curated, support-aware arrangements. It extends the existing room profiles, legacy memories, component sessions, furniture catalog and Forge exporter. The Game continues to load ordinary embedded glTF geometry; there is no second renderer or per-frame storytelling simulation.

See the [matched camera comparison viewer](evidence/forge-storytelling/index.html), [component inventory](evidence/forge-storytelling/component-inventory.json) and [archive integrity record](evidence/forge-storytelling/archive-integrity.json). Screenshots use the existing Game archive loader, floor streamer, material system and cinematic atmosphere in Chromium WebGL, with cameras at 1.62 m. They are render studies rather than screenshots of new gameplay interactions.

## Shared library and narrative ownership

`room_story_objects.mjs` supplies 30 reusable compound object templates in 11 semantic families. Full and compact forms use the existing material palette, with three stable variants and a bounded 32-entry cache. Callers receive independent copies. The shared Forge registry exposes them as `story-object:<id>`; geometry is generated by the existing material-batched architectural shape writer.

## Supporting surfaces and clearance

`furniture_surfaces.mjs` describes verified flat regions of nine existing furniture types: writing desk, laboratory bench, console, side table, dining table, banquet ensemble, supper table, bed and sarcophagus. Tests cast rays into the actual generated furniture meshes at nine points per safe region. Positions are transformed from furniture-local coordinates, including rotation; each object exports both world bounds and furniture-local support bounds for auditing.

Safe regions exclude rounded table edges, existing plates, task-lamp corners, pillows, bedposts and the sarcophagus cross. Props begin at the actual support height, with no arbitrary air gap. The existing banquet/supper plate bases were also lowered 15 mm to meet their table surfaces; collision footprints and furniture placements are unchanged.

One component session claims each `support:<furniture-id>` surface. The old generic support-object pass and opulence tabletop pass no longer compete with the narrative composition. Authored suitable furnishings are preferred, without moving or replacing them. Authored `allowAccessories:false`, nonempty `surfaceObjects` or `accessories` protect an occupied surface. Room-level `forgeDecoration.storytelling:false`, `{enabled:false}`, or a disabled `story-vignette` component suppress this new storytelling layer. Existing unrelated fixtures and furniture remain governed by their own policies.

Ordinary rooms receive one arrangement, with at most one secondary on a distinct support when area is at least 22 m² and detail is standard or higher. A row rotates along narrow dining runners. Packing retains a minimum 72% model scale and gaps between component bounds; the least important trailing cue is omitted before making everything illegibly small.

An unfurnished room with adequate height can receive a real wall shelf/frame supporting its objects above 2.18 m. Otherwise a shallow framed record occupies a safe wall span. Passages and stair/elevator spaces use only the shallow form. Existing wall mounting excludes doors, windows, removed walls and portrait reservations. These small projections remain in the existing wall clearance band and do not add route-blocking floor furniture or new colliders. If no safe span exists, geometry is omitted and reported.

## Budgets and export compatibility

Each object is capped at 1,600 triangles and nine material groups; the inventory records actual full/compact costs. A primary composition targets at most 2,400 triangles, or 1,000 in compact mode. The unchanged room/house component budgets remain authoritative: 420 primitives and 10,000 triangles per room; 14,000 primitives, 200,000 triangles and a 24 MiB geometry estimate per house, with fair allocations across rooms.

Budget rejection rolls back geometry, arrangement metadata and surface claims together. The planner retries a compact primary composition before falling back to a shallow clue. Reports distinguish density simplification, authored surface protection, no safe placement and session budget rejection. More legible hero objects take priority over small repeated accessories. The reported object count counts compound semantic templates, not every cup, ink stroke or flower petal.

No CASA manifest version or mandatory loading contract changes. `storyArrangements` and `storyDensity` are additive fields in room content. The optional `qa/environmental_storytelling.json` contains edition `environmental-story-1`, per-room arrangements/density/omissions, and `newRequiredObjectives:0`. Existing archives need no migration. All geometry uses existing material indices and the existing decoration GLB. No texture, shader, dynamic light or animation system is added. Templates are reused during compilation and their emitted geometry is batched by material; this is not a new runtime instancing extension, so each placement still contributes vertices to its archive.

## Limits

The objects are deliberately stylized, bounded meshes. Handwriting and labels are graphic marks, not readable generated prose. Specimen-bell glazing is frosted and can obscure interior stems in strong light; this pass adds no runtime refraction. Compact settings can omit supporting clues, so a secondary garment, garden tool or watch is not guaranteed in every room. A small wall record preserves narrative context when a full physical tableau cannot safely fit. The stress fixture exercises an L-shaped layout assembled from supported rectangular rooms; it does not introduce arbitrary polygon room geometry. No hardware frame-rate claim follows from software-rendered cloud screenshots.

No existing student archive is rebuilt in the working repository. Full tests that prepare sample houses run in a disposable copy. This pass is committed locally on the development branch without publication or deployment.
